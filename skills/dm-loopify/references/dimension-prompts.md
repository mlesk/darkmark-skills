# Starting dimensions by target type

Starting points for Phase 2, not templates. Pick what separates a weak version of this target from a strong one, then let the user reshape the list.

**Single artifact or document:** completeness, clarity, testability, scope precision, consistency, audience fit.

**Artifact set or workflow:** internal consistency, dependency clarity, handoff quality, coverage of every required piece, sequence correctness, operational usability.

**Workflow, prompt, or skill:** trigger precision, execution fidelity, shortcut resistance, scannability under time pressure, recovery from misuse, whether it actually controls behavior instead of only describing it.

**Subsystem or codebase:** correctness, reliability, maintainability, test coverage, integration safety, performance on the hot path, consistency with repo conventions.

**Goal with no baseline yet:** goal fit, feasibility, clarity of execution, risk surfacing, measurability, quality of the first concrete version.

**Open-ended creative target:** goal fit, distinctiveness, conceptual strength, memorability, feasibility, how clearly the chosen direction earns its boldness.

## Questions that surface dimensions

- If you graded this on 5-9 dimensions, what would they be? What separates weak from strong?
- What are the most common ways this kind of target fails?
- Which dimension measures actual goal attainment rather than polish?
- If originality matters, what captures point of view rather than generic polish?
- If this controls behavior (workflow, prompt, skill), what measures whether someone can shortcut it?
