# Loopify anti-patterns

Check the loop against these before the first round and before delivery.

| Anti-pattern | What it looks like |
| --- | --- |
| Approval theatre | Showing the rubric or baseline, then continuing without a reply. |
| Loopify in name only | Claiming the loop ran without a contract, approved rubric, baseline, and scored rounds. |
| No threshold | Looping because "better" was never given a number. |
| Rubric drift | Changing weights or anchors after scoring starts so the favorite wins. |
| Sandbagged baseline | Starting weak to manufacture a dramatic climb. |
| Self-flattery | Self-scoring every round when a blind judge was available. |
| Local-only scoring | Accepting a change because one slice improved while the whole got worse. |
| Artifact tunnel vision | Treating a codebase or document set as if it were one file. |
| Rewrite-everything fantasy | Reworking a whole codebase in one round instead of choosing a slice. |
| Premature convergence | Hill-climbing the first plausible direction without checking for a higher ceiling. |
| Refinement prison | Polishing when the real leverage is a different structure or concept. |
| Intentions as output | A round that leaves a plan to change things instead of changed things. |
| Convenience stop | Stopping because it is "decent now", not on threshold, plateau, or cap. |
| Plateau denial | Burning rounds after the search has clearly converged. |
| Rubber-stamp review | Showing the critic scores, rationales, or the hoped-for answer. |
| Unscored adoption | Applying a reviewer's suggestion without judging it against `best`. |
| Endless review | Re-running dm-critic after every fix. |
